# GT-R LAB architecture and execution plan

## Intent and boundaries
Original independent Nissan GT-R digital exhibition, not official Nissan or Porsche. The user requests premium visual storytelling, six accurate variant identities, real WebGL, meaningful controls, mobile access, documented legal assets, GitHub publication and Railway deployment. No copied reference code/assets, invented specs, fake 3D or six-label reskin. Asset readiness is an explicit product state.

## Design and stack
React, TypeScript, Vite, React Router, Three.js / React Three Fiber / Drei, Zustand. Static app served by a minimal Railway-compatible Node server with SPA routing. Dark neutral tokens, thin silver borders, restrained red, editorial sans headings. Native browser motion/CSS for UI; frame interpolation in Three for cameras/materials. Generated design concepts guide composition only; actual variant photography is rights-cleared and credited.

## Routes
`/` cinematic home, `/models` immersive model selector, `/configurator/:model` configurator, `/heritage` story, `/credits` asset/source/legal attribution. Direct links and browser Back/Forward work.

## Boundaries
- `data/models.ts`: source-backed variant records, image/license references, specifications, per-variant GLB manifest and material-name contract
- `data/configuration.ts`: conceptual paints, environments and camera presets
- `stores/configurator.ts`: selected variant/paint/environment/camera/rotation/lights/sound/details state; guarded localStorage
- `components/three`: renderer/error boundary, GLTF loader, material adapter, camera transition, studio lighting/environment and context-loss state
- `components/configurator`: toolbar/panels, swatches, detail sheet, asset fallback and progress
- `components/layout`, `pages`, `hooks`: site shell, focused route compositions, gesture-activated audio and reduced motion

## Asset contract
Each variant has its own source URL/path, attribution, readiness, material roles and optional part capabilities. Never load another car under a different badge. Missing vehicle asset produces a clearly labeled photographic reference view and explicit 3D-unavailable state; paint/camera/light controls only activate with real mesh. Local GLB inspection can load a user-selected licensed asset for the session without upload, clearly distinguished from approved catalog assets. Unknown GLB material roles are not changed heuristically.

## Real renderer
Perspective camera + OrbitControls, intelligently clamped zoom/polar angle. Smooth position/target/FOV transitions cancel on manual input. Physical clearcoat paint only for declared material names, original glass/rubber/carbon preservation, SRGB/ACES, contact shadows, adaptive DPR. Studio and architectural environment moods use original procedural lighting rigs and optional licensed HDRI. No primitive substitute car. Environment resources remain local where practical.

## State, errors and access
Panels use one controlled active panel, escape dismissal and focus return. Sound preference persists, AudioContext starts only via gesture, generated tones avoid stolen audio. Reduced motion disables auto-rotation and long movements. Genuine asset progress through loader manager, explicit retry on failed asset, context loss and unsupported WebGL. Recoverable app route error boundary. Keyboard-accessible labels and44px target minimum.

## Implementation plan
1. Complete observed reference audit and record unknowns (done)
2. Gather all six photos/licenses and manufacturer specifications; attempt approved meshes (in progress)
3. Generate/inspect homepage, models and configurator concepts, lock tokens
4. Implement tested structured data/state/route foundation; build homepage, lineup and heritage
5. Build honest per-variant GLB renderer and working configurator UI, accessible fallback, audio
6. Add build/type/unit/critical-flow checks and run; inspect browser desktop/mobile, failure/reentry/back paths
7. Red-team realism/legal/data/empty-controls/performance; fix or label evidence-backed blockers
8. Verify production build, commit/push via authenticated GitHub connector, deploy Railway when connection/cost authority exists, inspect live exact commit

## Definition of completion
Functional scaffold or a photographic fallback is not completion of required live premium3D. Report missing geometry/visual test/deployment blockers honestly; do not publish them as a finished product.

## Test sequence
- Data: tests/data.test.ts validates six identities, source URLs, asset honesty, race engine accuracy and units
- State: tests/store.test.ts validates variant cleanup, invalid option protection, manual orbit cancellation and exclusive panels
- Renderer: pure material/camera helpers unit tested; actual WebGL browser test still required
- Pages: semantic structure plus browser critical-flow validation including Back/reentry/Escape and failed loads
- npm test, npm run build and browser visual QA must be rerun on final tree
