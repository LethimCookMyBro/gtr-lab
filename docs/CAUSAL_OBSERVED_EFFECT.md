# Private executable causal observed-effect collector

Status: implementation and socket-free test fixtures only. No local browser,
server, socket or WebGL run. No publication. No real causal result is claimed.

## Narrow outcome, not schema laundering

The read-only producer in the exact reviewed production source emits the physical
main camera position/quaternion/projection, committed camera/vehicle state and
production native pacing fence lineage. It does **not** emit a handler-consumed
application epoch. The independently reviewed `r35-demand-final-request-v1` schema
is retained unchanged and remains insufficient. This collector is separately
named `r35-causal-observed-effect-v1`; it never fabricates `appliedInputEpoch` or
interprets CameraRig's requestId as an input counter.

For this pinned `useInteriorLook`, camera mutations happen synchronously in the
canvas input listener. A trusted event is recorded in document capture. Document
bubble, after the canvas handler, compares the actual physical pose with an
independently replayed mathematical target. A changed matching pose is reported
as `independent-physical-effect-observed`. Missing propagation, wrong event/owner,
interfering vehicle/dimension changes, wrong pose or untrusted input fail closed.
A clamped/no-op target already equal before the handler is **receipt only, with
consumption unproven**. It is never counted as a changed applied event.

This equivalence is intentionally narrower than a producer application epoch.
It depends on the exact source's synchronous listener implementation. It does
not assume that all future controller implementations have that property.

The original native generator's Node-side transport ledger is independent of
producer pose snapshots. All six 12-step drags, native dispatch order, exact
requested coordinates, keys, three seat requests, six light clicks, rotate
clicks, scaffolding, resize and waits are checked. Browser trusted receipts must
match that generator. Browser coordinate rounding has a maximum 1 CSS-pixel
receipt tolerance; expected pose is replayed from the actual trusted coordinates.
No software dispatchEvent input is generated by the runtime collector.

A seat click is reported as received. If the vehicle's committed seat and camera
destination/target/FOV reach the independently derived seat model before a newer
seat request, that logical state is recorded. If it already matched before the
click, consumption remains unproved; only a changed seat value is called an
observed logical change. These passive observations never
wait between Passenger, Rear and Driver. Intermediate seat presentation is not
claimed. A superseded unobserved commit remains unproved, not silently accepted.

## Independent cabin oracle

`causal-cabin-model.mjs` reproduces the native eye points, yaw/pitch deltas and
clamps, fixed-eye projection, arrow-key and wheel rules mathematically. It does
not import production controller code or use an observed applied pose as an
expected pose. Quaternion comparisons accept equivalent opposite signs with
an absolute component tolerance of 1e-8; position/projection use the same stated
floating-point tolerance. Exact view dimensions and material light intensities
are checked independently.

The model transform comes from the hash-pinned exterior GLB's normalized position
accessor bounds and node translation/scale, then the pinned normalization rule.
Unexpected hierarchy, rotation, skinning, morph targets or encoding fail closed.
The test compares that independent bounds calculation with separate Three AABBs.
Cabin entry/seat selection resets the oracle. The explicit original resize resets
interior look in this exact source because the memoized destination changes;
the sidecar independently models that behavior at the resize boundary.

Exterior OrbitControls damping and continuous rotation are **unresolved**. The
collector never copies observed exterior pose into an expectation. Captures
01–06 remain part of the 13-image workload; moving 04/05 receive observational
brackets but no settled-pose wait or false moving-image attribution.

## Native completion and image freshness

The sidecar consumes production `attach/main/fence/wait/retire` events. It calls
no GL method, creates no fence and schedules no animation callback or render.
Production source is pinned to its actual nonblocking `clientWaitSync(sync,0,0)`.
Only native ALREADY_SIGNALED or CONDITION_SATISFIED qualifies.

Fence supersession must inherit the pending main-draw IDs. A later fence with
only offscreen work still follows every earlier command on that same native
context: its completed prefix therefore covers an already completed earlier main
draw. The sidecar records `prefixDrawMax` separately from the producer's pending
`draws` list instead of pretending the producer listed earlier retired draws.
The latest prefix itself must positively complete. The final artifact validator
reconstructs that ancestry from ordered raw attach/main/fence/wait/retire records;
it does not trust the observer’s prefixDrawMax, completion or success flags. It
replays cabin input math and seat targets from the independently derived pinned
model config, checks every physical post-state, and ties each selected native
main to its final input or seat receipt/commit. Main completion and later
offscreen drain certificates remain separate. Unknown lineage, failed wait,
owner replacement, foreign default-buffer rendering or overflow invalidates it.

Canvas width/height setters chain after the unchanged original observer. Every
write advances buffer generation, even a same-size write. Old main draws cannot
qualify after a clear; a new genuine main draw is needed. No native writes are
added or suppressed. Live actual state, latest main and latest completed native
prefix must be identical in the before/after screenshot bracket.

Captures 07/08/09/10/12 need a fresh post-action completed matching main draw.
Only unchanged idle 11/13 may reuse the already certified draw, with identical
state, input ordinal, owner and buffer generation. For visible changed targets
08/09/10, independently masked scene pixels must change at identical mask
geometry. A resized layout is never treated as a pose-motion witness.

This is causal association of a fresh nonblank PNG with a stable native interval,
not a compositor frame ID. It cannot prove between-sample flicker, smoothness or
physical-device responsiveness.

## Original driver and budgets

`diagnose-dpr-motion.mjs` and both old observers are copied byte-for-byte. The
current policy is the independently reviewed published source-bound extension;
e9 policy bytes are separately retained in evidence/e9-motion-policy.mjs. `build-causal-driver.mjs` verifies the old
original driver SHA-256 and deterministically derives a separate executable,
with exact instrumentation anchors. The action body, 13 labels, input arguments,
75/100/350ms waits, 1s resize wait, 1.5s setup and 4s idles remain unchanged.

The sidecar's readiness shares the **original screenshot invocation** deadline:
45,000ms per attempt, at most two attempts inside the original 90,000ms envelope.
Readiness may consume that existing budget but never earns another attempt.
Only an actual `page.screenshot` TimeoutError with matching API provenance permits
the original second attempt. A browser or Node scheduling stall cannot resurrect
late evidence. Before/after verification and pixel-summary completion must also
fit that same attempt budget. No intermediate input is serialized by readiness.

These invariants preserve action order, arguments and explicit waits; they do not
claim identical wall-clock inter-capture pacing.

Readiness changes time spent *inside* the original screenshot transaction. Thus
assertions evaluated during this separate causal run are reported as the current
original assertions on the causal workload; they are not the exact historical
native run. The historical failed report bytes and hashes are separately preserved.
The original files and failed result are not overwritten or reclassified.
